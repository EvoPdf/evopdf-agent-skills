Generated from the XML documentation shipped in the EvoPdf Next NuGet packages.

## PdfSecurityOptions

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfSecurityOptions.htm

This class encapsulates the options to control the PDF document security like permissions, encryption, password protection

### Properties

- `CanAssembleDocument`: Can assemble the PDF document generated by the HTML to PDF converter (create bookmarks, thumbnail images or insert, rotate, delete pages). This property has effect when a 128 bit key is used.
- `CanCopyAccessibilityContent`: Can copy the PDF document accessibility content of the PDF document generated by the HTML to PDF converter.
- `CanCopyContent`: Can copy the content of the PDF document generated by the HTML to PDF converter.
- `CanEditAnnotations`: Can edit the annotations of the PDF document generated by the HTML to PDF converter.
- `CanEditContent`: Can edit the content of the PDF document generated by the HTML to PDF converter.
- `CanFillFormFields`: Can fill the form fields in the PDF document generated by the HTML to PDF converter. This property has effect when a 128 bit key is used. To disable form filling the CanEditContent and CanEditAnnotations must be set on false.
- `CanPrint`: Can print the PDF document generated by the HTML to PDF converter. When this property is set to false the printing of the PDF document is disabled in a PDF viewer.
- `EncryptionAlgorithm`: The encryption algorithm used to encrypt the PDF document generated by the HTML to PDF converter. When this property is not set, the RC4 algorithm is used for PDF 1.x documents and the AES algorithm is used for PDF 2.0 documents, like the PDF/UA-2 documents. PDF 2.0 documents encrypted with AES and a 256 bit key use the encryption revision 6 defined in ISO 32000-2.
- `KeySize`: The dimension of the encryption key in the PDF document generated by the HTML to PDF converter. When this property is not set, a 128 bit key is used for PDF 1.x documents and a 256 bit key is used for PDF 2.0 documents, like the PDF/UA-2 documents.
- `OwnerPassword`: The password required to change permissions of the PDF document generated by the HTML to PDF converter, like printing or editing. If the OwnerPassword property is an empty string and the UserPassword is not empty, the OwnerPassword will be automatically assigned with the value from UserPassword and when the PDF document is opened in the viewer using the user password (which is also the owner password) all the operations like printing, copying, etc will be allowed.
- `UserPassword`: The password required to open the PDF document generated by the HTML to PDF converter. If the OwnerPassword property is an empty string and the UserPassword is not empty, the OwnerPassword will be automatically assigned with the value from UserPassword and when the PDF document is opened in the viewer using the user password (which is also the owner password) all the operations like printing, copying, etc will be allowed.

## PdfDigitalSignature

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfDigitalSignature.htm

This class encapsulates the options used to control the digital signature applied to a PDF document

### Properties

- `Appearance`: Gets the object that controls the digital signature appearance in the PDF document. You can configure the page where the signature is displayed, the bounds in the PDF page, and the appearance text or image
- `AppearanceEnabled`: Gets or sets a value indicating whether the signature appearance is displayed in a PDF page using the configured page number and bounding rectangle
- `Certificate`: Gets the signing certificate given to the PdfDigitalSignature constructor, or null when another constructor was used
- `CertificationLevel`: Gets or sets the certification level of the signature. The default is NotCertified, an approval signature. The other values produce a certification signature (DocMDP), which declares the changes the document accepts after signing: none, form filling and signing, or also annotations. A certification signature must be the first signature of the document
- `ContactInfo`: Gets or sets the signer contact information
- `DigestAlgorithm`: Gets or sets the digest algorithm of the signature. The default is Sha256
- `ExternalSignature`: Gets the implementation that produces the signature value with a private key held outside the application, given to the PdfDigitalSignature constructor, or null when another constructor was used
- `ExternalSignatureSizeEstimate`: Gets or sets the maximum size in bytes of the signature value produced by ExternalSignature or with a Certificate, used to reserve space in the document before the signature is requested. The default of 512 bytes covers RSA keys up to 4096 bits and every ECDSA key
- `FieldName`: Gets or sets the signature field name in the PDF document. By default, it is null and a predefined field name is used. When the document already contains an empty signature field with this name, for example a form prepared with a field for each signer, the signature is placed in that field, on its page and in its rectangle, with the text and image of Appearance. A field that is already signed or that is not a signature field is refused
- `Location`: Gets or sets the signing location
- `PfxCertificateData`: Gets or sets the PFX certificate data provided directly in the constructor or loaded from the file specified in the constructor
- `PfxCertificatePassword`: Gets or sets the PFX certificate password provided in the constructor. It can be null if no password is required
- `Profile`: Gets or sets the PAdES baseline profile of the produced signature, as defined by ETSI EN 319 142-1. The default is Auto, which preserves the behavior of the previous versions: PAdES B-T when TimestampServerUrl is configured, PAdES B-B otherwise. The PadesBaselineLT and PadesBaselineLTA profiles additionally embed the certificate chains and their revocation information into the document and, for LTA, apply a document timestamp, enabling validation long after the certificates expire. Both long-term profiles require TimestampServerUrl to be set
- `Reason`: Gets or sets the signing reason
- `SignerCertificates`: Gets the certificate chain embedded in the signature, as DER encoded X.509 certificates ordered from the signer certificate to the highest known certificate authority: the chain stored in the PFX certificate, the chain given to the PdfDigitalSignature constructor or, for a Certificate, the chain found in the certificate stores of the system and in TrustedCaCertificates
- `TimestampServerPassword`: Gets or sets the optional password for the timestamp server, used together with TimestampServerUsername
- `TimestampServerUrl`: Gets or sets the URL of the timestamp server used when signing the document. Leave empty or null to skip timestamping
- `TimestampServerUsername`: Gets or sets the optional username for the timestamp server when it requires HTTP Basic authentication. Most public timestamp servers do not require it
- `TimestampTokenSizeEstimate`: Gets or sets the estimated size in bytes reserved in the signature for the timestamp token. The default is 16384 bytes, which works for most timestamp servers. Increase this value only if the timestamp server returns a token larger than the reserved space, which can happen with servers that include long certificate chains in the response
- `TrustedCaCertificates`: Gets or sets an optional set of additional trusted certificate authority certificates, as DER encoded X.509 certificates. They complete the chain of a Certificate and, when producing PadesBaselineLT or PadesBaselineLTA signatures, the signer and timestamp certificate chains whose issuers cannot be located through the Authority Information Access extension of the certificates

## PdfDigitalSignatureAppearance

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfDigitalSignatureAppearance.htm

This class encapsulates the options used to control the appearance of the digital signature applied to a PDF document

### Properties

- `BoundsRectangle`: Gets or sets the appearance bounding rectangle in the PDF page, relative to the top-left corner of the PDF page
- `DisplayOnLastPage`: Gets or sets a value indicating whether the appearance is displayed on the last page of the PDF document instead of the specified page number. The default value is false
- `KeepAspect`: Gets a value indicating whether the aspect ratio of the image is preserved, as specified in the SetImage() method call
- `PageNumber`: Gets or sets the page number, starting at 1, on which to display the signature appearance. By default, the page number is 1. If the page number is larger than the total number of pages in the PDF document, the signature appears on the last page
- `Text`: Gets or sets the text to display in the appearance. It can be null, in which case default text is displayed, containing the signer common name, signing date, reason, location and signer contact information, if they were set. The text is positioned at the top of the bounding rectangle

### Methods

- `SetImage`: Sets the background image to display in the appearance based on image data. The image format is automatically determined from the data. The supported formats are Jpeg, Png and Webp
- `SetImage`: Sets the background image to display in the appearance based on the full path to an image file. The image format is automatically determined from the image data. The supported formats are Jpeg, Png and Webp

## PdfDigitalSignatureProfile

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfDigitalSignatureProfile.htm

The PAdES baseline profile applied when digitally signing a PDF document, as defined by ETSI EN 319 142-1. Higher profiles embed progressively more material into the document so the signature can be validated long after the signing certificate expires

### Fields and values

- `Auto`: The signature level is selected automatically from the other signature settings, preserving the behavior of previous versions: when TimestampServerUrl is configured the produced signature is PAdES B-T, otherwise PAdES B-B
- `PadesBaselineB`: PAdES Baseline-B: a CAdES signature with the signing certificate attribute. The signing time is declared by the signer and there is no independent proof of when the document was signed
- `PadesBaselineLT`: PAdES Baseline-LT (long-term): Baseline-T extended with a Document Security Store embedding the certificate chains and their revocation information (OCSP responses, or CRLs when no OCSP responder is available), so the signature remains verifiable without any external service, even years after the certificates expire. Requires TimestampServerUrl. The revocation information is downloaded during signing from the URLs published in the certificates, so signing requires network access. A revoked certificate refuses the signature
- `PadesBaselineLTA`: PAdES Baseline-LTA (long-term with archive timestamp): Baseline-LT extended with a document timestamp that seals the whole document including the embedded validation data, enabling decades-long archival. Requires TimestampServerUrl. For very long retention periods the document timestamp should be periodically renewed before its certificate expires
- `PadesBaselineT`: PAdES Baseline-T: Baseline-B extended with an RFC 3161 signature timestamp obtained from the configured timestamp server, providing independent proof of the signing time. Requires TimestampServerUrl

## IExternalDigitalSignature

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_IExternalDigitalSignature.htm

Implement this interface to produce the signature value with a private key that never enters the application process: a hardware security module accessed over PKCS#11 or a cloud key service such as Azure Key Vault or AWS KMS. A certificate of the system store, a smartcard or a USB token can be given directly to the PdfDigitalSignature constructor instead. The library prepares the PDF signature structures, computes the CMS signed attributes, calls Sign to obtain the signature value from the external device, and embeds the result. All PAdES baseline profiles are supported with external signing

### Methods

- `GetSignatureAlgorithmName`: Returns the signature key algorithm name: "RSA" for RSASSA-PKCS1-v1_5, "RSASSA-PSS", "DSA" or "ECDSA". The digest of the signed attributes is the one configured in DigestAlgorithm
- `Sign`: Signs the given message, which contains the DER encoded CMS signed attributes, with the configured digest algorithm and returns the signature value produced by the external device or service. ECDSA and DSA values can be returned DER encoded or as the concatenation of r and s, the form produced by the .NET ECDsa class

## PdfLongTermValidationOptions

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfLongTermValidationOptions.htm

The options used by AddLongTermValidation to add long-term validation data to the signatures of a PDF document. When TimestampServerUrl is set, a document timestamp is added after the validation data

### Properties

- `TimestampServerPassword`: Gets or sets the password for the timestamp server, when the server requires authentication
- `TimestampServerUrl`: Gets or sets the URL of the RFC 3161 timestamp server used for the document timestamp added over the validation data. When this property is not set, only the validation data is added
- `TimestampServerUsername`: Gets or sets the user name for the timestamp server, when the server requires authentication
- `TimestampTokenSizeEstimate`: Gets or sets the estimated size in bytes reserved for the document timestamp token. The default is 16384 bytes
- `TrustedCaCertificates`: Gets or sets an optional set of additional certificate authority certificates, as DER encoded X.509 certificates, used to complete the certificate chains that cannot be completed from the issuer URLs published in the certificates

## PdfSignatureField

Reference: https://www.evopdf.com/help/evopdf-next-dotnet/html/T_EvoPdf_Next_PdfSignatureField.htm

An empty signature field placed in a page of the document, to be signed later by a digital signature with the same field name. A form with a field for each signer is prepared this way, and each signer fills in a field in turn

### Properties

- `Description`: The description of the field shown by PDF viewers as a tooltip and read by assistive technology. The field name is used when it is not set
- `Height`: The height of the field, in points
- `Name`: The field name. A digital signature with this field name is placed in the field
- `PageNumber`: The 1-based number of the page where the field is placed
- `Width`: The width of the field, in points
- `X`: The left position of the field in the page, in points
- `Y`: The top position of the field in the page, in points
